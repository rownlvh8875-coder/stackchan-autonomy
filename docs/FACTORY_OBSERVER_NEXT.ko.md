# GPT 대화 다음: 실제 관찰과 자율 동작으로 가는 순서

현재 완료: 출고 K151·공식 앱을 유지하는 **GPT API 답변 → 로봇 음성** 현장 PASS.
다음으로 선택한 방향은 **공식 펌웨어 기반 PC 연결 확장안 준비**다.
이 선택은 실제 기기의 펌웨어 설치나 모터 작동 승인이 아니다.

## 준비한 첫 단계와 다음 확인

**USB 관찰 전용 연결**을 권장한다. PC가 카메라 사진 한 장과 터치/IMU 이벤트를 읽고,
명시적으로 이미지 전송을 켠 경우 GPT가 사진을 설명하게 하는 단계다.
기존 GPT 텍스트 대화는 유지하고, 관찰 기능은 별도 선택 기능으로 둔다.
모터·표정·LED 명령은 이 관찰 모듈에 넣지 않는다.

| 순서 | 만들고 확인할 결과 | 실제 기기 상태 |
|---|---|---|
| 1 | 펌웨어 확장 설계, PC 연결 규약, 복구·호환성 조건 | 현재 출고 상태 유지 |
| 2 | 관찰 모듈·PC 클라이언트·GPT 이미지 입력의 코드와 오프라인 검증 | 설치하지 않음 |
| 3 | 실제 ESP32-S3 빌드·백업·복구 및 공식 앱 호환성 검토 | 사용자 설치 승인 대기 |
| 4 | 승인 후 사진·센서 읽기와 기존 음성 기능의 동시 사용 확인 | 관찰만 시험 |
| 5 | 제어권·실제 STOP·각도 피드백과 작은 동작 검증 | 별도 모터 승인 필요 |
| 6 | 관찰 → GPT 판단 → 검증된 동작 → 결과 평가 | 이후 장시간 운용 검증 |

## 공식 소스에서 확인한 제약

2026-11-17에 공식 main SHA를 확인했으며 기준은
`28b9f0c8bd6acd81cb3c70f1a93c3e373b39d400`이다.

- 현재 앱 MCP 주소는 PC 도구 등록 경로다. 로봇 카메라/모터에 PC가 접속하는 주소가 아니다.
- 공식 Avatar LAN은 휴대폰이 서버를 열고 로봇이 접속한다. 공개 소스의 서버 주소/RSA
  설정은 배포 입력이어서, 현재 MCP 접속주소나 OpenAI API 키로 대체할 수 없다.
- 공개 펌웨어의 `secret_logic.cpp`에는 대체 인증값이 들어 있다. 소스에서 새로 빌드한
  펌웨어를 위한 제품 인증 구현/설정 경로는 공개되지 않았다고 공식 저장소 기여자가
  확인했다. [인증·LCD·USB 검토 기록](validation/2026-11-17-k151-recovery-compatibility.md) 참고.
  공식 서비스·앱 유지 조건의 설치는 현재 HOLD이며, 백업만으로 이 문제가 해결되지 않는다.
- 각도 조회는 실제 ReadPos가 실패했을 때 추정값으로 돌아갈 수 있다. 초기 관찰 연결에서는
  이를 물리 제어에 쓸 수 있는 정확한 현재 자세로 취급하지 않는다.
- 원래 부팅 과정에 서보 초기화와 조건부 NVS 지우기가 있다. 백업·복구·호환성 검토 전에
  시험용 이미지를 설치하면 안 된다.

따라서 먼저 확장 코드와 PC 연결을 검증 가능한 형태로 준비하고, 기존 기기의 동작을
바꾸는 결정은 정확한 빌드/복구 자료가 갖춰진 뒤에 한다. 제조사 키를 추출하거나
채팅으로 요청하는 방식은 사용하지 않는다.

[승인한 설계](superpowers/specs/2026-11-17-factory-usb-observer-design.md)에 따라
관찰 코드·PC 클라이언트·선택적 GPT 이미지 도구를 준비했다.
[설치 전 확인과 후속 작업설명서](USB_OBSERVER.ko.md)를 따른다.
[현재 단계의 원본 백업·복구 준비](K151_BACKUP_RECOVERY.ko.md)는 집에서 COM 조회부터 시작한다.
개발 검증과 실제 ESP32 빌드는 [검증 기록](validation/2026-11-17-usb-observer.md)에 구분한다.
실물 설치·카메라·센서·음성 동시 사용 시험은 아직 하지 않았다.
