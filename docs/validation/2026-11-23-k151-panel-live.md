# K151 화면·머리 터치·STOP 실물 시험과 출고 복구

별도로 승인받아 화면·머리 터치·STOP 진단 이미지를 한 번 임시
설치했다. 시험 전에 같은 ESP32-S3와 16MiB 플래시, 보안 상태,
파티션 표·OTA 선택 데이터와 원본 OTA1 해시를 대조했다.
[진단 이미지 ESP32-S3 빌드](https://github.com/rownlvh8875-coder/stackchan-autonomy/actions/runs/45052849735)

| 항목 | 결과 |
|---|---|
| 진단 이미지 해시 | `897b88ce2260b0ebbec0b8cc5aa7ef440d56d1f9da0b1df0155ec3d07a8df7bd` |
| 임시 쓰기 | `ota_1 [0x510000,0x58D390)`, 512,912바이트 |
| 영향을 받은 섹터 | `ota_1 [0x510000,0x58E000)` |
| 설치 후 독립 검증과 재부팅 요청 | 통과 |
| 진단 START 및 화면·머리·STOP | 호스트 START 기록과 진단 결과 없음 |
| 출고 슬롯 복구 | `ota_1 [0x510000,0xA00000)`, 5,177,344바이트, 독립 해시 검증 통과 |
| 복구 후 파티션 표·OTA 선택 데이터 | 출고 백업과 일치 |
| 출고 부팅과 확인 | 재부팅 요청 성공, Windows COM3 복귀, 사용자가 출고 얼굴 또는 메뉴 확인 |

수집기는 초기 시작 확인을 마치지 못했다. 복구를 시작한 시각은
진단 부팅 요청 완료 뒤 약 10.1초였다. 같은 수집기의 승인·이미지·설치
기록 대조는 사후 오프라인에서 통과했다. 당일 수집기는 초기 실패의
세부 사유를 기록하지 않았다. 펌웨어 부팅, COM 열기, 첫 응답 중
어디서 멈췄는지는 확인이 필요하다. 화면, 머리 센서, 물리 STOP은
이번 결과로 판단할 수 없다.

승인된 1회 설치 범위에서 복구까지 마쳤다. 오디오·Wi-Fi·유료 요청을
포함하지 않는 진단이었으며, 음성 녹음과 외부 전송은 없었다.
