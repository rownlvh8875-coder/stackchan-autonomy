# K151 응답 버퍼 메모리 검증

기준 `347801b3f8536bb0f012bc51c464683feabd04a3`. 재생 PCM을 디코딩하는
동안 원본 응답 body와 질문이 살아 있는 경로를 확인했다. 세 본문의 합계는
2,304,000바이트다. 기존 512KiB 여유를 더한 사전검사 PSRAM 기준은
2,828,288바이트다. 실제 heap과 TLS 동시 peak를 요구하는 조건은 유지한다.

기존 C++ 테스트에서 speech body를 1KiB씩 채웠을 때 960,000바이트 본문 한도를
넘는 vector capacity를 재현했다. 성장 요청의 상한을 유효한 Content-Length
또는 endpoint 한도로 두어 시험을 통과했다. 6바이트 선언을 4+2바이트로 읽는
경우와 최대 speech body의 declared/chunked 두 경우도 확인했다.

기존 무음 자원 진단은 모델과 질문을 유지한 상태에서 실제 bounded receiver와
decoder를 연결했다. 256KiB JSON 및 960,000바이트로 생성한 합성 무음 PCM을
사용한다. JSON 파싱은 큰 문자열 하나를 사용하며 parser 최악 peak를 대표하지
않는다. JSON 디코딩 이후의 heap 최소치는 누적 watermark다. speech 단계는
응답 원본과 변환된 PCM이 모두 살아 있는 동안 힙과 배치를 관측한다.
이후 기존 64개 무음 chunk 추론을 이어 간다. USB에는 결과와 집계치만 표시한다.
동시 TLS handshake, network, 실제 마이크와 DMA는 아직 미측정이다.

- Windows Python 500 통과, 2 SKIP. 선택 의존성 포함 standalone 625 통과,
  5 SKIP. 기존 5개 SKIP 중 Linux cJSON 경로는 공개 cJSON 1.7.19
  `c859b25da02955fef659d658b8f324b5cde87be3`를 Windows에서 C로 별도
  컴파일해 실제 decode/최대 payload/STOP 중단 시험을 실행했다.
- 단일 독립 검토에서 짚은 PSRAM 문서 불일치와 짧은 Content-Length 경계
  시험을 반영했다. 수정 후 집중 wire/admission 2개가 통과했다.
- COM3은 PnP 조회로 확인했다. 원본 A/B와 별도 디스크 사본 세 개는 모두
  16,777,216바이트이며 기존 SHA256과 일치한다. 로봇 포트를 열거나 쓰지 않았다.
- 실제 ESP32-S3/CI 결과는 [PR #3](https://github.com/rownlvh8875-coder/stackchan-autonomy/pull/3)에
  해당 커밋과 함께 기록한다. 기기 설치와 실물 실행은 검토한 이미지별로 승인받는다.
