# K151 무음 WakeNet 입력 경로

기존 NativeWakeController의 FIR과 유한 chunk 버퍼를 같은 코드에서
무음 진단도 쓰도록 분리했다. 컨트롤러는 세션 epoch, 100ms 입력
간격, AudioGuard 및 일회성 호출 권한을 계속 관리한다. 입력 경로는
형식 16kHz 모노 PCM16, chunk 160..2048을 검사하고, 마이크 읽기와
모델 호출 전후에 동의와 모델 형식을 확인한다. STOP, 형식 변경과
오류에서는 부분 chunk와 FIR 이력을 폐기한다.

Windows C ABI 시험은 실제 K151CodecPort와 K151MicReader에서 가짜
I2S 프레임을 읽고, 공통 입력 경로로 512샘플 감지 콜백을 실행했다.
두 프레임이 쌓인 뒤 입력 권한을 닫아 읽기와 추론을 차단했다.
새 입력으로 네 프레임을 채운 뒤 감지되는지 확인했다. 감지 반환과
동시에 STOP을 설정한 경우 감지 대신 오류를 반환했다. 기존 세션
epoch, STOP/resume, 부분 읽기 및 DSP 시험도 실행한다.

기존 64개 합성 모델 chunk 기록을 유지한다. 그 뒤 새 단계는 모델을
reset하고 합성 24kHz 무음 프레임 32개를 공급한다. 24kHz 프레임과
중간 PCM은 메모리에서만 존재하며, USB는 처리 결과와 최댓값만
기록한다. 무음 감지 또는 모델·입력 오류가 나면 단계가 실패한다.
입력 버퍼 객체는 힙에 두고 PCM은 기존 non-elidable wipe로 지운다.

현재 장치의 전원·클록·앰프 격리와 실제 마이크 FIFO·STOP 시간은
미측정이다. 운영 `app_main`은 HOLD다. 이번 단계의 포트 접근, 리셋,
펌웨어 쓰기, 실음성 수집, 유료 API는 0회다. 실제 호출어 인식과
독립 GPT 대화는 별도 실물 시험으로 남아 있다.
