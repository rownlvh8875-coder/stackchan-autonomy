# WakeNet 모델 컨텍스트 재생성으로 reset

직전 계측의 마지막 수신 지점은 `model_reset_begin`이었다.
`model_reset_return` 전에 ESP-IDF `ESP_RST_PANIC` 재부팅을 관측했다.
당시 reset 구현은 ESP-SR의 `clean()`을 호출했다. 실제 예외 주소와
SDK 내부 원인은 미확정이다. [이전 실물 기록](2026-11-21-k151-wake-reset-panic-live.md)

## 변경과 소유권

- `K151WakeNetPort::reset()`은 이전 컨텍스트를 먼저 파기한다. 이미
  검증한 모델 목록의 같은 이름과 `DET_MODE_90`으로 새 컨텍스트를
  생성한다. 검증한 목록과 SDK의 전역 loader 소유권은 reset 동안
  유지하며, 컨텍스트 두 개가 동시에 존재하지 않는다.
- 새 컨텍스트의 sample rate, mono 채널, 단일 호출어, PCM16 형식과
  정확한 chunk 크기가 기존 형식과 같아야 한다. 지원 범위는
  160..2048 그대로다. 불일치나 생성 실패는 포트를 fault로 만들고
  컨텍스트와 모델 목록을 해제한다.
- 파티션 및 내장 자산 경로가 받은 로컬 동의·STOP을 reset 전, 기존
  컨텍스트 파기 뒤, 새 컨텍스트 생성·포맷 확인 뒤 검사한다. 두 플래그는
  포트보다 오래 살아야 한다. HAL 호출 중 일어난 조건 변경은 반환 뒤
  확인하며 물리 선점 지연은 별도 시험 대상이다. 임시 플래그와 bool의
  암시적 임시 변환은 컴파일 단계에서 거부한다.

운영 HOLD, 100ms 입력 간격, 오디오 지움, 호출 수위, 모델·자산 검증
및 클라우드 기본 OFF를 유지한다. SDK `create`와 `destroy`의 대상은
각각 개별 모델 컨텍스트다. [고정 ESP-SR 헤더](https://github.com/espressif/esp-sr/blob/2f8c4b0459db5bbb39abd77adae27962d6d94bcb/include/esp32s3/esp_wn_iface.h)

## 오프라인 검증과 범위

기존 코드의 `clean()` 호출, 대체 생성 실패에서의 성공 반환, 파기 중
동의 철회 검사를 새 ABI 시험으로 실패시켰다. 수정 뒤 새 컨텍스트의
초기 상태, 두 컨텍스트의 비동시성, loader 재로딩 방지, 포맷 변화와
취소·생성 오류에서의 종료를 확인했다. 실제 포트를 SDK 대역과 결합한
합성 벤치 시험에서 512샘플 64개 직접 추론, 24kHz 합성 32프레임,
두 번의 reset, 11개 계측 경계까지 실행했다.

독립 검토에서 두 자산 진입점이 수명이 짧은 임시 플래그를 허용하는
경우를 확인했다. 컴파일 실패 회귀를 추가하고 기존 lvalue 호출을
유지하면서 rvalue 호출을 막았다.

최종 집중 회귀는 127개 통과로, 모델 포트 ABI·무음 벤치·기존 호출
컨트롤러 검증을 포함한다. 로컬 수신기도 모의 포트로 완료, 중복 시작,
START flush 오류의 기존 종료 동작을 별도로 확인했다.

실제 마이크 또는 SDK 내부의 panic을 호스트에서 재현하지 않았다. 새
컨텍스트의 실제 ESP32-S3 생성·해제 지연과 메모리, 실제 호출어 인식과
독립 대화는 장치 시험을 기다린다. 이번 단계의 포트 접근, 리셋, 쓰기,
실음성 수집, 유료 API 호출은 0회다.
