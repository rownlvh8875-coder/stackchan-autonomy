## 보드 및 사용자 관측

호스트는 기존 호출어 수신 안내와 질문 안내를 띄웠고, 로컬 START를 한 번
전송했다. 수집기가 두 레코드와 종료 HOLD를 확인했다.

| 필드 | 값 |
|---|---|
| WakeNet `MIC_WAKE_TRIAL_V2` | `detected`, `complete` |
| 호출어 수신 프레임 | 288개, 전부 0인 프레임 6개, PCM16 끝값 샘플 0개 |
| 질문 `MIC_QUESTION_TRIAL_V1` | `endpoint` |
| 코덱 해제 불확실성 | 두 결과 모두 `false` |
| 운영 모드 진입 | 두 결과 모두 `false` |

사용자는 안내 뒤 “Hi StackChan”만 한 번 말했고 짧은 질문은 말하지
않았다고 확인했다. 호출어 감지는 이 시험에서 확인됐다. 질문을 말하지
않은 상태에서 `endpoint`가 반환됐으므로 질문에 대한 오탐이다.
이 레코드로는 어떤 입력이 발화 시작 조건을 충족했는지 확인할 수 없다.
질문 종료 판정은 60ms 연속 에너지와 뒤따르는 500ms 기준 미달 입력을 검사한다.
USB에는 발화 내용, 질문 PCM과 입력 시각별 크기를 포함하지 않는다.
실제 음성 파일 저장과 외부 전송, 스피커 재생, 유료 API 호출은 0회였다.
독립 STT/GPT/TTS 한 턴은 실물 검증 전이다.

## 오프라인 재현과 수정

WakeNet은 감지 이벤트를 반환한다. 이어지는 질문 진단은 기존 코덱을
해제하고 새 RX 채널을 열었지만, 처음 프레임부터 질문의 발화 시작
조건에 포함했다. 새 채널에서 60ms 연속으로 RMS 기준 이상인 입력이
들어온 뒤 500ms 동안 기준에 미달하면 질문 없이도 `endpoint`가 될 수 있었다.

실제 K151 포트와 질문 분리기 코드에 모의 I2S 입력을 연결했다. 전환 직후
80ms의 높은 에너지와 이후 기준 미달 입력만 공급한 시험은 수정 전
`endpoint`로 실패했다. 이 재현은 전환 입력을 질문과 구분하지 못하는
코드 경로를 확인한다. 지난 실물 시험의 고정 레코드로는 호출어 소리의
잔여분, RX 초기화 구간의 신호, 주변 소리 중 어떤 입력이 원인이었는지
특정할 수 없다.

질문 전용 진단은 새 RX에서 기존 RMS 기준에 연속 25프레임(500ms)
미달한 뒤에만 질문 안내를 보낸다. 기준을 넘는 프레임이 끼면 연속
카운트를 다시 시작한다. 안내까지 읽은 입력은 질문용 PSRAM에 복사하지
않으며 기존 프레임 지움 경로를 사용한다. 안내 전 한도를 소진하면
`quiet_timeout`, 안내 뒤 발화 종료 없이 한도를 소진하면
`no_endpoint`를 반환한다. 400프레임·8초의 질문 한도와 START 이후
10초의 전체 한도 안에 대기 시간도 포함된다.

회귀 시험은 초기 신호만 있는 경우의 `no_endpoint`, 안내 직후 유효한
합성 질문의 `endpoint`, 중간에 끊긴 조용한 구간, 연속 기준 미달 없이
소진된 시간 한도, 정확히 마감 때 조용해진 입력을 검사했다. 안내 전
STOP·부분 읽기, 안내 뒤 동의 철회·부분 읽기, 코덱 해제 실패와 PCM 지움도
확인했다. USB 검사기는 안내 전 `quiet_timeout`과 읽기 실패를 구분하고
종료 HOLD를 요구한다. 개인 호출어 경로와 기존 에너지 문턱은 유지했다.
이 수정의 검증 범위는 오프라인 시험이다. 적용 뒤 실물 결과는 아래에 기록한다.

## 수정 이미지의 호출어 단독 대조

2026-11-22 KST에 질문 안내 전 500ms 기준 미달 입력을 요구하는 코드

로컬 START 한 번 뒤 호출어 수신 안내와 질문 없이 기다리라는 안내가
차례대로 표시됐다. 사용자는 호출어만 한 번 말하고 질문 없이 조용히
기다렸다고 확인했다. 수집기는 아래 두 레코드와 종료 HOLD를 검증했다.

| 관측 항목 | 기록 |
|---|---|
| WakeNet `MIC_WAKE_TRIAL_V2` | `detected`, `complete` |
| 호출어 수신 프레임 | 365개, 전부 0인 프레임 6개, PCM16 끝값 샘플 0개 |
| 질문 `MIC_QUESTION_TRIAL_V1` | `stopped` |
| 코덱 해제 불확실성 | 두 결과 모두 `false` |
| 운영 모드 진입 | 두 결과 모두 `false` |
| 호스트의 START 발송 직전 기록에서 결과 저장까지 | 10.029초 |

시험은 질문에 대한 `endpoint`를 보고하지 않았다. `stopped`는
정상적인 `no_endpoint` 완료와 구분한다. 호스트 파일 시각 차이는
펌웨어 전체 10초 제한과 일치하지만, 종료 레코드에 세부 정지 원인은
없다. 질문 구간의 실제 관찰 시간은 호스트 시각 차이로 측정할 수 없다.
따라서 수정 이미지의 실물 오탐 대조는 판정 보류다. 실제 음성 파일
저장·외부 전송·스피커 재생·유료 API 호출은 각각 0회였다.
