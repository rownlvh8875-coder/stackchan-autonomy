## 보드 및 사용자 관측

호스트는 기존 호출어 수신 안내와 질문 안내를 띄웠고, 로컬 START를 한 번
전송했다. 수집기가 두 레코드와 종료 HOLD를 확인했다.

| 필드 | 값 |
|---|---|
| WakeNet `MIC_WAKE_TRIAL_V2` | `detected`, `complete` |
| 호출어 수신 프레임 | 288개, 전부 0인 프레임 6개, PCM16 끝값 샘플 0개 |
| 질문 `MIC_QUESTION_TRIAL_V1` | `endpoint` |
| 코덱 해제 불확실성 | 두 결과 모두 `false` |
| 운영 모드 진입 | 두 결과 모두 `false` |

사용자는 안내 뒤 “Hi StackChan”만 한 번 말했고 짧은 질문은 말하지
않았다고 확인했다. 호출어 감지는 이 시험에서 확인됐다. 질문을 말하지
않은 상태에서 `endpoint`가 반환됐으므로 질문에 대한 오탐이다.
이 레코드로는 어떤 입력이 발화 시작 조건을 충족했는지 확인할 수 없다.
질문 종료 판정은 60ms 연속 에너지와 뒤따르는 500ms 기준 미달 입력을 검사한다.
USB에는 발화 내용, 질문 PCM과 입력 시각별 크기를 포함하지 않는다.
실제 음성 파일 저장과 외부 전송, 스피커 재생, 유료 API 호출은 0회였다.
독립 STT/GPT/TTS 한 턴은 실물 검증 전이다.

## 임시 설치와 출고 복구

쓰기 전에 같은 보드, 보안 설정, 16MB 플래시, 원본 A/B와 복구 파일의
길이·SHA256, 보드 파티션 표·OTA 선택 데이터 및 원본 슬롯 digest를
검증했다. SHA256
`91367b493b421cf9296b53022a0896a2862e8a0821a5154bdfaca20aa1c2420c`의
앱을 `ota_1 [0x510000,0x5BD3C0)`에 709,568바이트 임시로 썼다.
지우기 범위는 `[0x510000,0x5BE000)` 712,704바이트였고, 부팅 전
이미지 digest를 별도 확인했다.

실행 뒤 원본 `ota_1 [0x510000,0xA00000)` 전체 5,177,344바이트를
복구했다. 복구 플래시가 원본 슬롯 SHA256
`39280cbec8d01362c559cedce7d8cd088d951096a5d8f045ead27fe6bf9038fb`와
일치함을 독립 검증했다. 파티션 표와 OTA 선택 데이터는 쓰기 전,
시험 뒤, 복구 뒤 세 시점에 일치했다. 출고 부팅 요청과 COM3 복귀를
확인했다. 사용자가 평소 출고 얼굴 또는 메뉴의 복귀를 확인했다.

| 작업 | 벽시계 시간 |
|---|---:|
| 쓰기 전 원본 슬롯 검증 | 9.658초 |
| 질문 앱 쓰기 | 12.479초 |
| 질문 앱 독립 검증 | 1.990초 |
| 질문 앱 부팅 요청 | 0.717초 |
| 출고 슬롯 전체 복구 | 84.447초 |
| 복구 슬롯 독립 검증 | 9.704초 |
