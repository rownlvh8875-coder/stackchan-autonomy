2026-11-22 KST에 사용자가 이미지 설치, 호출어 1회 시험과 같은 슬롯
원본 복구를 승인했다. 브랜치 코드는 `5860cc9a30aee8a4f0db4e025a47496b20424095`,
빌드 checkout은 `23ed759efa8a9f7f4340c272a8340cc04dde82ae`다. 해당 빌드의
앱·ELF·내장 모델의 결합과 SHA256을 Windows에서 다시 검증했다.
[ESP32-S3 빌드](https://github.com/rownlvh8875-coder/stackchan-autonomy/actions/runs/44993638879)

## 실행 결과

- 현재 COM3의 동일 ESP32-S3, 보안 설정, 원본 백업 A/B 및 복구 파일을
  확인했다. 현재 파티션 표, OTA 선택 데이터와 원본 슬롯 전체도 쓰기 전
  검증했다.
- SHA256 `9531d2bda10c2cdea778b174d529a5d394d8b69e184beacef857d4d95a5fee62`
  앱의 705,632바이트를 `[0x510000,0x5BC460)`에 썼다. 실제 지우기 범위
  `[0x510000,0x5BD000)`와 독립 digest를 확인했다.
- 승인된 진단 부팅 뒤 새 로컬 코드에 START를 한 번 보냈다. 수집기는
  `MIC_WAKE_TRIAL_V1`의 `fault`와 종료 HOLD를 관측했다. 수신 시작
  표식과 프레임 집계는 관측하지 못했다. 수집기 종료 코드 0은 결과
  수신과 프로토콜 검증 성공을 가리킨다.

## 출고 상태 복귀

`ota_1 [0x510000,0xA00000)` 전체 5,177,344바이트를 원래 파일로 복구했다.
복구 SHA256은 `39280cbec8d01362c559cedce7d8cd088d951096a5d8f045ead27fe6bf9038fb`
이며 독립 검증을 통과했다. 파티션 표와 OTA 선택 데이터는 쓰기 전, 진단 뒤,
복구 뒤 세 시점에서 원본과 일치했다. 재부팅 요청 뒤 Windows에서 COM3이
돌아왔고 사용자가 평소 출고 얼굴 또는 메뉴가 보인다고 확인했다.

이번 승인으로 수행한 시험은 1회다. 실제 “Hi StackChan” 감지와 독립
GPT 대화는 미검증이다. 현재 고정 `fault` 결과만으로 모델 준비, 보드
레지스터 확인, 코덱 열기, 해제 중 어느 경계에서 실패했는지 특정할 수
없다. 해당 경계의 고정 상태를 남기는 오프라인 검증이 다음 작업이다.
실제 음성 파일 저장과 외부 전송, 유료 API 호출은 0회였다.
