# PC GPT 연결 자동 복구와 Windows 간편 실행

현재 출고 펌웨어·공식 앱으로 사용하는 PC GPT 연결을 위한 기능이다.
MCP 연결이 일시적으로 끊기면 새 연결을 만들며, 이전 GPT 질문은 자동 재전송하지 않는다.
기기 백업·새 펌웨어 설치나 USB 카메라 준비와 별개로 사용할 수 있다.

## 집에서 업데이트 후 실행

기존 연결 창을 Ctrl+C로 종료하고, 같은 MCP 주소를 사용하는 프로그램은 하나만 실행한다.
cmd에서 먼저 업데이트한다.

```cmd
git -C "%USERPROFILE%\stackchan-soak-24h" pull --ff-only
```

업데이트 뒤 환경을 한 번 준비한다. 필요한 패키지 다운로드는 이 명시적인 준비 단계에서
수행하며, 실제 실행 파일은 준비된 `.venv` Python만 사용한다.

```cmd
"%USERPROFILE%\.local\bin\uv.exe" --directory "%USERPROFILE%\stackchan-soak-24h" sync --frozen
```

기존 노트북의 `.env` 설정은 그대로 사용한다. 다음 한 줄로 간편 실행한다.
탐색기의 저장소 `scripts` 폴더에서 `start-gpt.cmd`를 두 번 클릭해도 된다.
파일을 저장소 밖으로 옮기지 않는다. 경로의 공백과 현재 cmd 폴더에 영향을 받지 않도록
실행 파일이 자신의 저장소 폴더를 찾아간다.

```cmd
"%USERPROFILE%\stackchan-soak-24h\scripts\start-gpt.cmd"
```

`Official MCP endpoint (hidden input):`에 공식 앱의 현재 MCP 주소를 넣는다.
주소는 실행할 때 한 번 입력하며 같은 프로세스의 재연결에서는 다시 묻지 않는다.
주소를 파일에 자동 저장하지 않는다. 키·접속주소는 채팅이나 GitHub에 올리지 않는다.
키·모델·cloud 설정이 누락되면 접속 전에 고정 코드와 한국어 안내로 중단한다.
준비된 Python 환경이 없거나 불완전하면 `PC_PYTHON_ENV_REQUIRED`와 준비 명령만
표시한다. 실행 파일이 자동으로 환경을 만들거나 패키지를 내려받지는 않는다.
설정 방법은 [기존 GPT 설명서](GPT_ROBOT.ko.md)를 따른다.

직접 실행하려면 아래 명령을 사용한다.

```cmd
"%USERPROFILE%\.local\bin\uv.exe" --directory "%USERPROFILE%\stackchan-soak-24h" run --frozen stackchan-pc-mcp --gpt --reconnect
```

`--reconnect`가 없는 기존 실행은 단일 연결 모드다. 설정은 프로그램을 새로 실행할 때
읽는다. 키·모델·MCP 주소를 바꿨다면 Ctrl+C로 끝내고 새로 실행한다.

## 화면 표시와 중단

| 표시 | 의미 |
|---|---|
| `OFFICIAL_MCP_INITIALIZED` / `PC_GPT_READY` | 새 MCP 세션 준비; 실제 API 응답 성공은 별도 |
| `OFFICIAL_MCP_RECONNECT_WAIT=2` | 일시 오류 후2초 대기; 한국어로도 안내 |
| `OFFICIAL_MCP_RECONNECTING=1` | 첫 재연결 시도 |
| `PC_GPT_CALLED=N` / `PC_GPT_ANSWERED=N` | 현재 연결의 GPT 호출·검증된 응답 |

연속 실패하면 대기는 **2→4→8→16→32→60초**, 이후60초다. 초기화 후60초 이상
유지된 세션 뒤에는 대기가2초부터 시작한다. 이전 연결의 HTTP·예산 작업 정리가
끝나야 다음 연결을 시도한다. 노트북 절전/전원 종료는 프로그램을 계속 실행시키지 않는다.
현재60초 계산에는 종료 정리 시간도 포함된다. 경계 근처에서 정리가 오래 걸리면
대기가 예상보다 먼저2초로 돌아갈 수 있는 경미한 제한이 있다.

연결 끊김 감지에는 운영체제·핑 제한 시간이 걸릴 수 있다. 즉시 재연결을 보장하지 않는다.
종료는 **Ctrl+C**이며 대기 중에도 종료할 수 있다. 배치 종료 여부를 묻는다면 Y로 종료한다.
치명적인 오류 때는 창을 열어 둬 안내를 읽을 수 있게 한다. 창을 닫으면 프로그램도 종료된다.

인증 거부401/403, 연결 제한429, 기타4xx, 인증서/보안 연결 오류, 잘못된 주소·규약·리디렉션은
자동 반복하지 않는다. 일시 네트워크·서버5xx·정상/일시 종료는 복구 대상으로 구분한다.
인증 오류 때는 앱의 현재 MCP 주소를 다시 확인한다. 보안 검증을 끄는 설정은 사용하지 않는다.

## 질문·사용량·대화 기억

연결이 끊길 때 처리 중이던 질문이나 결과는 재생하지 않는다. 이미 API에 전달한 요청은
답변을 못 들었어도 과금될 수 있다. 다시 연결한 뒤 필요하면 사용자가 새로 질문한다.
서버가 보내는 새로운 도구 호출은 별개의 요청이며 분산 시스템의 정확히 한 번 과금까지
보장하는 기능은 아니다. API 자체의 자동 재시도는 계속0회다.

새 연결에서는 확인 코드·호출 번호·짧은 RAM 대화 기억이 새로 시작한다.
**SQLite의 요청/사용량 한도는 유지**되므로 재연결로 한도가 초기화되지 않는다.
질문·답변·주소·키·원시 서버 오류는 정상 콘솔에 기록하지 않는다.

이 기능은 진단/텍스트 GPT 연결에 한정한다. 실험적인 `--observer-port`와 함께 쓰면
실행 전에 오류로 중단한다. USB 사진 요청이나 물리 장치 재접속을 자동 반복하지 않는다.
공식 앱 인증을 유지하는 새 펌웨어 설치는 [기존 호환성 HOLD](K151_BACKUP_RECOVERY.ko.md) 상태다.

## 집에서 할 짧은 확인 — 진단 복구·GPT 모드 복귀 확인 완료

2026-11-18(한국 시간)에 사용자가 제공한 Windows cmd 출력에서 단절 감지,
2→4→8초 대기 후 3회차 재접속, 재초기화·새 확인 코드·툴 목록 공개를 확인했다.
이어 GPT 간편 실행 파일의 READY와 공식 앱의 GPT 도구 등록을 확인했고,
사용자가 ANSWERED 표시와 정상 로봇 답변도 확인했다.
[진단 복구·GPT 복귀 현장 PASS 기록](validation/2026-11-18-mcp-reconnect-live.md)을 참고한다.
아래는 같은 확인을 다시 수행할 때의 순서다. GPT 처리 중 단절 시험은 별도다.

첫 시험은 API를 사용하지 않는 진단 모드로 할 수 있다. 기존 GPT 프로그램을 먼저
종료하고 아래 모드 하나만 실행한다.

```cmd
"%USERPROFILE%\.local\bin\uv.exe" --directory "%USERPROFILE%\stackchan-soak-24h" run --frozen stackchan-pc-mcp --reconnect
```

초기화를 확인한 뒤 노트북 Wi-Fi를 잠시 끊었다 복구하고, WAIT/RECONNECTING 다음에
새 INITIALIZED와 새 연결 확인 코드가 나오는지 확인한다. 이 모드에는 유료 GPT 도구가 없다.
Ctrl+C로 종료한 뒤 GPT 간편 실행으로 돌아와 새 질문의 ANSWERED와 실제 음성을 확인한다.
자동 시험은 로컬 WebSocket·실제 SDK의 MockTransport를 쓴다. 현장에서는 진단 연결
복구와 이후 별도로 시작한 GPT 모드의 답변·음성을 확인했다. 유료 요청 도중 단절이나
GPT 세션의 음성 자동 복구까지 확인한 것으로 확대하지 않는다.
