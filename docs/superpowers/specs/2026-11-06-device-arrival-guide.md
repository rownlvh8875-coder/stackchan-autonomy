# 제품 도착 후 작업설명서 설계

사용자 요청: 택배 수령부터 실물 장치 검증까지, 제품 매뉴얼을 확인해 기존 흐름도에
맞는 상세 작업설명서를 작성하고 GitHub에 올린다. Windows PowerShell 사용자를 기준으로 한다.

## 산출물

- `docs/DEVICE_ARRIVAL_RUNBOOK.ko.md`: 개봉, 출고 시험, PC 준비, 복구 준비,
  호환성 결정, 읽기 전용 연결, 물리 어댑터 개발, 단계별 실물 시험과 장시간 운용.
- `docs/templates/DEVICE_ACCEPTANCE_RECORD.ko.md`: 실제 결과를 채우는 로컬 기록 양식.
- README와 기존 bring-up 문서에서 새 설명서로 이동하는 링크.

## 제약

- 공식 M5Stack 제품/복구 매뉴얼과 프로젝트 소스의 사실을 구분한다.
- K151/K151-R 이외 제품, 교체 컨트롤러, LCD 개정판은 호환성을 추정하지 않는다.
- 첫 부팅의 제조사 서보 시험은 실제 움직임이라는 사실을 먼저 설명한다.
- 출고 StackChan World와 커스텀 MCP gateway는 서로 다른 연동 경로다.
- 실제 execute/capture/listen/say 차단을 해제하지 않는다. 존재하지 않는 hardware CLI를 쓰지 않는다.
- 펌웨어 교체, 모터 시험, 매체 전송에는 대상과 범위를 정한 별도 실행 승인이 필요하다.
  이번 요청은 설명서 작성과 GitHub 업로드이며 이 실행 승인을 대신하지 않는다.
- PC Mock 24시간과 실물 24시간을 구분한다. 사용자 PC의 완료 보고서는 아직 미확인이다.
- 비밀키, Wi-Fi 비밀번호, 원본 매체, 기기 식별자는 공개 기록에 넣지 않는다.
- 소스·의존성·환경 설정은 변경하지 않는다. 원래 개발 지시서는 그대로 둔다.

## 검수 기준

각 단계에 시작 조건, 실제 작업, 통과 기준, 실패 시 조치, 다음 담당자가 있다.
복사 가능한 Windows 명령은 현재 CLI와 맞아야 한다. 읽기 전용 예시는 쓰기 도구를 호출하지
않아야 한다. 실물 후속 단계의 미구현 부분은 보류 조건으로 표시한다. 출처 URL/확인일,
흐름도, T1–T10 실물 판정표, 결과 양식이 포함돼야 한다.
