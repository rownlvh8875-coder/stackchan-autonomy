# K151 독립 GPT 음성 펌웨어 설계

2026-11-18, Asia/Seoul. 상태: **검토용 설계, 구현 승인 전**.
현재 실물에는 출고 펌웨어가 실행 중이다. 이 문서의 검토·구현 승인은 설치 승인이 아니다.

**호출 방식 수정:** 사용자는 호출어로 **“조수야”**를 선택했고 최초 로컬 음성 등록도
가능하다고 확인했다. 이 문서는 터치 시작안에서 기기 내 호출어 감지안으로 수정했다.
제스처는 첫 구현 필수 조건이 아니다. 아래 구현 방식·수치·검증 기준은 구현자 제안이며
수정 설계의 구현 승인은 대기 중이다. 초기 검토와 별개로 호출어 변경안도 빌더 검토를 마쳤다.

호출어 검토 근거: 고정 소스의 `firmware/sdkconfig.defaults`에는
`CONFIG_SR_WN_WN9L_HISTACKCHAN_TTS3`가 있고, Xiaozhi의 custom wake-word 설정은
중국어 병음과 Multinet 모델에 의존한다. 이 설정만으로 임의의 한국어 이름을 지원한다고
판정하지 않는다. 현재 재사용 후보에서 공중 손가락 모양 인식 구현은 확보하지 않았다.
머리의 Si12T 터치/스와이프 감지는 카메라 제스처나 손가락 튕김 소리 인식의 근거가 아니다.

고정 빌드의 ESP-SR2.4.7뿐 아니라2026-11-18에 조회한
[공개 최신 소스 README](https://github.com/espressif/esp-sr/blob/bb552f1a559396a17681299cb3e199a0f1a4520a/README.md)도
한국어 TTS 호출어 학습을 예정으로, MultiNet을 중국어/영어 지원으로 명시한다.
“조수야” 전용 감지기를 직접 만들거나 별도 검증된 모델을 확보해야 한다.
대기 음성은 기기 내 유한 RAM 창에서만 감지하고 대기 중 STT/GPT로 보내지 않는 방향이다.
호출어와 질문을 구분하고, 로봇 자신의 재생 음성으로 새 요청이 생기지 않게 해야 한다.
사용자의 최초 로컬 음성 등록 동의에 따라 아래 언어 독립적인 특징/템플릿 인식 방식을
첫 시제품으로 제안한다. 등록 몇 회만으로 안정적인 한국어 인식이 보장된다고 주장하지 않는다.

## 목적과 확인된 선택

로봇이 집 Wi-Fi로 OpenAI API에 직접 연결해 한국어 질문을 듣고 GPT 답변을 말한다.
평상시에는 노트북·공식 StackChan World 앱·별도 중계 서버를 실행하지 않는다.
로봇 전원과 인터넷, 사용자의 API 계정/키는 필요하다.
이후 카메라·터치·IMU를 GPT 판단에 연결하고 자율 동작으로 확장한다.

사용자가 확인한 것은 제조사 문의 취소, 직접 개발, 공식 앱은 필수가 아니라는 조건이다.
노트북 없이 GPT를 사용하려는 앞선 요청도 따른다. ESP-IDF/C++, REST 음성 파이프라인,
아래 수치 제한·특징 기반 인식 방식은 구현자가 제안한 선택이며 아직 동의받은 수치가 아니다.

## 검토한 접근

| 접근 | 결과와 비용 |
|---|---|
| 기존 공식 MCP + Windows GPT 브리지 | 실물 음성 PASS지만 노트북 실행이 필요하다. 계속 사용할 수 있는 기존 경로로 보관한다. |
| 별도 상시 중계 서버 | 노트북을 대체하지만 서버 운영이 추가된다. 사용자가 가진 상시 장비 없이 직접 연결하려는 목적에 맞지 않는다. |
| 로봇 자체의 OpenAI 연결 | 노트북 상시 실행을 없앤다. 대신 기기의 음성·설정·UI·네트워크를 직접 구현하고 검증해야 한다. 이 문서의 제안이다. |

기존 Python SDK/SQLite 엔진을 MCU에서 실행하지 않는다. 고정 ESP-IDF/C++와
K151 하드웨어 드라이버를 바탕으로 별도 실행 경로를 만든다. 출고 서비스의 비공개
인증·OTA·공식 앱 호환은 의존성에서 제거한다. 공개 드라이버 재사용 시 출처·라이선스를 남긴다.

## 첫 구현의 결과물과 범위

첫 구현은 **직접 GPT 음성 대화용 펌웨어와 PC에서의 설정/진단 도구, 실제 ESP32-S3
빌드 및 오프라인 검증**이다. 실물 쓰기·유료 요청은 이 구현 작업에서 실행하지 않는다.

- 기기 내에서 “조수야”를 감지하고 준비음을 낸 뒤 질문을 받는다. 질문 종료는 무음 감지와
  최대8초 제한으로 처리한다. 질문은 준비음 뒤에 말하는 첫 버전의 흐름을 안내한다.
- 한국어 음성 전사 → GPT 응답 → 음성 합성 → K151 스피커 재생 경로를 구현한다.
- 얼굴/화면에 준비·녹음·생각·재생·연결 오류·한도·중지 상태를 표시한다.
- USB로 Wi-Fi/API 키/모델을 한 번 설정한 뒤, 이후 정상 부팅은 PC 없이 가능하게 한다.
- 설정/호출어 등록이 끝난 부팅에서 로컬 감지를 시작한다. 첫 설정 전에는 입력을 시작하지
  않는다. 등록/감지와 질문 전송 상태를 구분해 표시하고 질문 재전송·모터 명령은 없다.

첫 버전은 호출어 대기 상태로 계속 켜 둘 수 있다. 대기 중 마이크 입력은 계속 처리하지만
유한 RAM 창만 유지하고 파일 저장/클라우드 전송하지 않는다. 자동 사진 전송·
먼저 말하기·모터 자율제어는 후속 단계다. 기존 공식 앱의 감시 카메라/에이전트/업데이트
화면은 이 개발 펌웨어에서 제공하지 않는다. 기존 PC 브리지 코드는 그대로 사용 가능하다.

## 실제 기기와 저장 배치 근거

[실물 확인](../../validation/2026-11-18-k151-usb-preflight.md): K151, ESP32-S3 rev0.2,
16MB flash, USB Serial/JTAG COM3. Secure Boot/Flash Encryption은 꺼져 있다.
원본 A/B 각16MB는 사용자 로컬에서 같은 SHA256이며, 정상 부팅·기존 GPT·공식 앱
카메라 표시를 사용자가 확인했다. 실제 복구 쓰기와 별도 저장장치 사본은 미확인이다.

2026-11-18에 사용자가 로컬 진단 도구의 SHA/파티션 MD5 PASS와 다음 배치를 보고했다.
에이전트가 원본 바이너리를 받거나 독립 재계산한 기록은 아니다.

| 파티션 | 시작 | 크기 |
|---|---:|---:|
| nvs | 0x00009000 | 16,384B |
| otadata | 0x0000d000 | 8,192B |
| phy_init | 0x0000f000 | 4,096B |
| ota_0 | 0x00020000 | 5,177,344B |
| ota_1 | 0x00510000 | 5,177,344B |
| assets | 0x00a00000 | 4,194,304B |
| coredump | 0x00e00000 | 65,536B |

두 앱 슬롯이 있다는 사실로 활성 슬롯이나 덮어써도 되는 슬롯을 판정하지 않는다.
아직 실제 OTA 선택 데이터/앱 유효성은 해석하지 않았다. 빌드 크기는 한 슬롯 이하로
검사하지만 설치 주소/부트 선택은 별도 실물 계획에서 확정한다. 기본 flash 명령은 만들지 않는다.

## 구조와 재사용

- `firmware/standalone/`: 독립 엔트리포인트·K151 하드웨어 계층·C++ 상태/예산/HTTP
  모듈·고정 의존성·빌드 설명. 원본 공용 소스와 도구 캐시는 git-ignored 경로에 둔다.
- 기존 `firmware/observer/dependencies.json`의 StackChan/ESP-IDF 고정 SHA를 출발점으로
  삼는다. 필요한 공개 하드웨어 코드만 적용하고 제조사 AI 앱 전체를 시작하지 않는다.
  새 관리 의존성을 선택하면 정확한 버전/해시를 별도 manifest에 기록한다.
- 카메라 최신성/SCOB core와 Python 중지·예산·인 메모리 데이터 처리는 계약의 근거로
  재사용한다. 첫 음성 구현을 카메라/모터 구현까지 완료한 것으로 표시하지 않는다.
- 독립 설정 도구는 기존 `stackchan-pc-mcp`와 별도 명령이다. 기존 실행/설정/테스트는
  변경하지 않는다. USB 장치는 자동 선택하지 않고 확인된 포트를 명시한다.

## 부팅·하드웨어·상태

BOOT → 설정/호출어 확인 → Wi-Fi/TLS 준비 → WAKE_WAIT → READY → RECORD → TRANSCRIBE → THINK →
SYNTHESIZE → PLAY → COOLDOWN → IDLE. 설정 누락은 SETUP_REQUIRED,
호출어 미등록은 ENROLL_REQUIRED, 장치/저장 오류는 ERROR, 사용자의 중지는 STOPPED로
표시한다. 정상 완료 후 IDLE은 WAKE_WAIT로 돌아간다. 네트워크 복구 중 감지 정책은
새 유료 작업을 시작하지 않는 범위에서 구현자가 정하고, 상태를 화면에 표시한다.

기존 `Hal::init()`을 그대로 호출하지 않는다. NVS 자동 삭제·서보 초기화·공식 AI/MCP·
설정 화면 연결을 제외한 명시적 초기화 순서를 만든다. 전원/I2C/IO 확장/LCD/터치/
오디오를 필요한 순서로 구성하고, 오래된 assets 파티션을 필수로 사용하지 않는다.
전원 정책은 USB 전원에서 자동 종료하지 않는 대기 동작을 목표로 하며 배터리 상태
오류를 실제 전원 증거로 위장하지 않는다. 전원/온도/배터리 검증은 실제 운영 시험 대상이다.

오디오 설정 근거는 고정 소스의24kHz 입력/출력과 ES7210/AW88298이다. 입력 참조 채널을
분리해 유효 PCM16 모노만 전사에 사용한다. 기존 읽기 오류를 양의 샘플 수로 반환하는
경로를 재사용하지 않는다. 재생은 PCM16→하드웨어 TX 슬롯 변환과 실제 쓰기 결과를 검증한다.
첫 볼륨은 낮게 제한하고, 전원/코덱 오류 시 녹음/재생을 시작하지 않는다.

한 작업만 허용한다. 녹음 중 짧은 터치는 보조 종료로 남기며, 다른 작업 중 새 대화 요청은 버린다.
화면의 중지 또는 길게 누르기1초로 중지 latch를 우선 설정하고 녹음/네트워크/재생을
취소·폐기한다. 수동 재개 전에는 새 요청을 보내지 않는다. RST/전원은 OS와 독립된
기존 물리 복귀 수단이다. 소프트웨어 중지는 이미 서버에 도착한 유료 요청을 취소하거나
기기의 전기적 토크를 제거한다고 보장하지 않는다. 첫 구현은 서보 UART 명령을 내지 않는다.

## “조수야” 로컬 감지와 최초 등록

첫 구현자의 제안은 **짧은 음성 구간의 MFCC 계열 특징 + 등록 템플릿의 DTW 거리**를
쓰는 개인화된 호출어 시제품이다. 중국어 모델에 한국어 문자열을 넣거나 인식된 다른
호출어를 “조수야”로 표시만 바꾸지 않는다. TensorFlow 학습 서버나 제조사 맞춤 모델
서비스를 운영하지 않고, 임의 발화 전체를 유료 STT에 보내 호출어를 찾지도 않는다.
이 선택은 정확도가 미검증인 가설이며, 아래 실측을 통과해야 실제 대화 활성화로 간다.

- 실제 로봇 마이크의 입력으로 등록해 PC 마이크와의 차이를 줄인다. 첫 펌웨어 설치를
  별도로 결정한 뒤, 등록할 때만 USB로 노트북에 연결해 로컬 도구 안내에 따라 발음한다.
  이 단계에서는 클라우드 기능을 끄고 SCFG의 명시적인 등록 모드로만 입력을 받는다.
- 제안 수집량은 “조수야”10회와 다른 말/생활 소음10개 구간이다. 긍정5회는 템플릿/보정,
  나머지5회는 등록 시 독립 검증에 쓴다. 부정 구간으로 거절 기준을 보정한다.
  같은 녹음을 학습과 검증 양쪽에 넣지 않는다. 실물 최종 평가는 새 발화로 한다.
- 원시 등록 음성은 기기의 유한 RAM에서만 처리한다. MCU가 특징을 추출해 노트북에는
  제한된 특징 구간만 보내고, 로컬 도구가 템플릿/거절 기준을 보정한다. PC 마이크/외부 녹음
  프로그램이나 Windows 사용자의 C++ 컴파일러 설치에 의존하지 않는다. 남기는 것은 기기용
  특징 blob과 버전/보정값이다. 특징은 인 메모리 또는 git-ignored 로컬 파일로만 다루고
  임시 파일 정리 경로를 안내한다. 원시 음성/특징은 GitHub나 API로 보내지 않는다.
- 마이크의24kHz 모노를 anti-alias 필터로16kHz로 변환한다. 유한 최대3초 구간에서
  특징을 만들고 최대3개 템플릿, 각64 time bins ×13 int8 특징으로 제한한다.
  추출/정규화/양자화 버전을 고정하고 host와 MCU에 같은 core/기준 벡터를 적용한다.
  정확한 DSP 창/거절 임계값은 구현자가 정하고 fixture·실측 근거를 남긴다.
  host core 실행은 개발/CI 검증이다. 사용자 도구의 정수 DTW 계산은 그 기준 벡터로
  일치 여부를 검사하며, 사용자 PC에서 DSP를 다시 컴파일하거나 raw 녹음을 처리하지 않는다.
- 등록 특징은 최대4KiB의 version/hash/길이 검증 blob으로 새 namespace에 저장한다.
  원본 NVS 공간이 충분하다고 가정하지 않는다. 설정+예산+특징 commit 공간이 부족하면
  ENROLL_REQUIRED/저장 오류를 표시하고 중단한다. 자동 NVS 삭제나 다른 파티션 쓰기는 없다.
- 등록 특징은 SCFG의 유한 청크(각4KiB 이하, sequence/nonce/최종 길이 검증)로만 보낸다.
  원시 PCM 전송 명령은 추가하지 않는다. 한 구간 최대3초, 끊긴 청크는 폐기하며 자동
  재녹음하지 않는다. 등록 모드와 GPT 대화는
  동시에 실행하지 않는다. 등록된 특징의 결과 ACK에 raw 음성/비밀 값을 넣지 않는다.
- 평상시 최근 최대3초의 입력만 RAM에 둔다. 음성 구간이 끝나면 로컬 거리를 검사하고,
  기준을 만족할 때만 READY로 간다. 어떤 목소리의 소유자인지 인증하는 기능은 아니다.
- 준비음 뒤 최대5초 기다려 질문이 시작되지 않으면 WAKE_WAIT로 돌아간다. 질문 시작 뒤
  무음 약1초 또는 최대8초에서 종료한다. 비어 있거나 코덱 오류인 입력은 전송하지 않는다.
  최종 무음/잡음 임계값은 실측해 정한다. 호출어 구간은 STT/GPT 입력에 포함하지 않는다.
- READY/질문/처리/재생 중에는 호출어 감지를 중복 실행하지 않는다. 재생 완료 후 최소500ms
  동안 감지를 쉬고 입력 버퍼를 비운 뒤 복귀한다. 중지 상태는 감지까지 끈다.
- 감지 실패/미등록을 터치 시작이나 다른 호출어로 자동 대체하지 않는다. 자동으로 다른
  모델/클라우드 상시 인식을 켜지 않는다. 시제품 성능 미달이면 미완료로 보고한다.

## 호출어의 완료 기준

오프라인 host 검증은 특징의 언어/타이밍/무음/잡음·잘린 구간·등록 버전/길이/저장 오류·
템플릿 최대 크기·콜백 중복/중지·자기 재생 억제와 버퍼 해제를 다룬다. 합성 파형이나
거리 fixture만으로 한국어 인식률을 주장하지 않는다.

설치 후 실측 제안은 조용한 실내1m에서 학습에 쓰지 않은 “조수야”20회 중18회 이상 반응,
일반 말/생활 소음60분에서 잘못 깨는 횟수1회 이하, 로봇 재생20회에서 자기 호출0회다.
실제 소음·거리·발화자·미응답/오반응 수를 모두 기록한다. 호출 뒤 준비음/질문을 기다리는
첫 버전의 사용 조건으로 평가한다. 시끄러운 TV/음악 속 인식이나 다른 사람의 인식률을
이 결과로 보장하지 않는다. 반응시간·CPU/메모리·USB 없는 재시작도 계측한다.

이 기준을 통과하지 못하면 호출어 기능을 완료로 판정하지 않는다. 템플릿 보정으로
해결되는지 먼저 확인하고, 필요하면 별도 한국어 소형 모델로 접근을 다시 검토한다.
성능 미달을 숨기려고 대기 음성을 API로 보내는 방식으로 바꾸지 않는다.

## 설정과 개인정보

USB 연결은 개발·최초 설정·문제 진단 때만 사용한다. Wi-Fi SSID/비밀번호, OpenAI 키,
응답/STT/TTS 모델과 TTS voice를 소유자의 로컬 설정 파일/숨김 입력에서 읽어 전송한다.
키를 소스·빌드 옵션·GitHub·채팅·일반 로그에 넣지 않는다. 모델은 명시적으로 설정하고
현재 PC에서 쓰는 모델 이름을 기기에 설정할 수 있다. 실제 모델 접근 권한은 실물 API
검증 전에는 보장하지 않는다. 다른 AI 제공자로 자동 전환하지 않는다.

별도 USB 설정 계약은 기존 읽기 전용 SCOB v1과 구분한다. `SCFG` magic/version1,
요청 nonce·길이·CRC가 있는 고정 프레임, 최대8KiB payload, 명시적 설정/호출어 등록/상태/중지만
허용한다. 상태/ACK는 키·SSID·원문 요청을 돌려주지 않는다. CRC는 인증이 아니며 소유자의
물리적 USB 연결이 신뢰 경계다. 일반 콘솔/로그와 같은 바이트 스트림에 섞지 않는다.
오류는 고정 코드이며 개행 포함 비밀 값/미등록 명령을 echo하지 않는다.

유효한 전체 설정을 새 `sc_gpt` NVS namespace의 버전 있는 blob으로 저장한다.
기존 제조사 namespace/키를 읽어 추출하거나 수정하지 않는다. **새 namespace 쓰기도
기기 NVS 바이트를 변경한다.** 원본 백업 파일 불변과 기기 NVS 불변을 혼동하지 않는다.
남은 NVS 공간이 부족하거나 버전/초기화/commit 오류면 중단하며 format/전체 erase를 하지 않는다.
NVS는 현재 단말에서 암호화되지 않았으므로 암호화된 비밀 저장소라고 설명하지 않는다.

녹음·전사·답변·합성 음성은 한 작업의 RAM에만 유지하고 완료/취소 뒤 해제한다.
평상시 대화 이력과 원시 데이터의 영속 저장을 하지 않는다. 최초 명시 등록의 제한된 특징
템플릿은 위 예외로 구분한다. 이미지 전송은 구현하지 않으며 후속 관찰 모드에서
별도 명시 설정으로 켠다. 부팅 후에는 등록/설정이 유효할 때 로컬 호출어 감지만 시작한다.

## 직접 API와 자원 한계

고정된 `https://api.openai.com/v1`에 인증서 검증을 켠 HTTPS로만 연결한다.
인증서/시각 확인 실패 시 요청하지 않는다. 임의 base URL·HTTP redirect·디버그 body
로그를 허용하지 않는다. SNTP 준비 전에는 영속 시간 예산을 초기화하거나 API를 보내지 않는다.

1. WAV(24kHz/16bit/mono, 최대8초384,000B + header)를 `/audio/transcriptions`로 전송,
   `language=ko`, JSON 전사문 최대500 Unicode 문자만 허용한다.
2. `/responses`에 전사문·짧은 한국어 지침을 보낸다. `store=false`, 출력 최대400tokens,
   추출한 답변 최대300 Unicode 문자. 응답의 오류/누락/잘못된 구조는 실패 처리한다.
3. `/audio/speech`에 답변을 보내 PCM24kHz/16bit/mono를 받아 실제 스피커로 재생한다.
   최대20초960,000B를 RAM에 완전히 받은 뒤 재생하며 초과/부분/홀수 바이트는 폐기한다.

요청당30초, 전체 작업90초의 유한 deadline. HTTP/JSON 응답은256KiB 이하로 제한한다.
오디오 binary는 위 별도 한도를 적용한다. chunked 전송/Content-Length/UTF-8과 오류
status를 검증하며 서버 오류 body를 그대로 로그에 남기지 않는다. 자동 API retry는0회다.
네트워크 복구는 다음 대화의 연결을 준비할 뿐 중단된 질문을 다시 청구하지 않는다.
Wi-Fi 재연결은 최대60초 backoff로 기다리며 화면에 상태를 표시한다.

카메라는 첫 음성 작업의 메모리를 점유하지 않는다. 실제 PSRAM 용량/가용량·내부 DMA/TLS
버퍼·task 수를 계측하고 할당 실패는 고정 오류로 종료한다. 목표8MB PSRAM을 실측한
사실로 취급하지 않는다. 정확한 buffer 재사용·태스크 크기는 구현자의 결정으로 남긴다.

## 비용과 재시작

텍스트 PC 브리지와 달리 음성 한 번에는 최대3회의 유료 요청이 필요하다.
이 설계의 제안 한도는 rolling60초2작업/6요청, rolling1시간30작업/90요청,
rolling24시간100작업/300요청이다. 계정 전체 사용량/달러 청구 한도가 아니다.
이 새 한도를 기존 PC CLI의 예산 설정에 덮어쓰지 않는다.

첫 유료 전송 전에 작업과3요청을 함께 영속 예약한다. 실패/취소/중간 단계 미사용도
예약을 환불하지 않으며 재부팅 후 반복 요청으로 예산을 되살리지 않는다. 한 작업의
timestamp/예약 수만 보관하는 bounded ledger(24시간 최대100작업)를 별도 namespace에
저장한다. 원시 문장·오디오·키는 ledger에 없다. 저장 실패·시간 역행·잘못된 ledger는
새 유료 요청을 막고 소유자에게 고정 오류로 알린다. 정확한 NVS commit 구성은
구현자가 정하되 예약의 원자성/재시작/저장 오류 계약을 검증한다.

## 검증과 설치 경계

구현 완료로 판정할 범위:

- 실제 C++ 상태/프레이밍/예산/HTTP 파싱 코드를 host fixture로 실행한다. 녹음 오류·
  재생 실패·timeout/STOP·늦은 응답·소진·재부팅 예약 유지·저장 실패를 검증한다.
- 합성 WAV/한국어 JSON/PCM으로 STT→Responses→TTS 요청과 결과를 검증한다.
  실제 계정 호출은 하지 않는다. USB 설정 프레임의 오류/길이/비밀 비노출도 검증한다.
- 호출어 특징/DTW/등록/중복 억제의 같은 C++ core를 host/실제 ESP32 링크에서 검증한다.
  실제 한국어 양성/부정 음성의 성능은 별도 실물 결과로만 남긴다.
- 실제 ESP32-S3 toolchain으로 독립 엔트리포인트와 하드웨어 어댑터를 링크한다.
  소스/의존성/빌드 설정/ELF/app SHA와 한 슬롯 크기 검사를 manifest로 남긴다.
  host mock pass를 ESP32 빌드나 실제 녹음 성공으로 부르지 않는다.
- 기존 Python/Linux/Windows CI에 영향을 주는 부분만 해당 검증을 하고, 설정 도구를
  추가하면 Windows cmd 실행/패키징도 검증한다. 새 런타임을 기존 가상24시간 PASS로 판정하지 않는다.
- 소유자가 검토할 설치/복귀 문서를 작성하되 실행하지 않는다. 생성물에
  `NOT_APPROVED_FOR_DEVICE_INSTALLATION`을 명시한다.

첫 실물 시험 전에는 실제 활성 OTA/앱 상태, 별도 백업 사본, 정확한 app 이미지/주소/
bootloader 호환·부트 선택, 원본 복귀 절차, NVS 새 쓰기와 공식 앱 대체 영향을 검토한다.
그 구체적인 결과를 놓고 설치를 별도로 결정한다. full-flash 이미지나 bootloader/
파티션 표/assets/NVS를 기본 설치 대상으로 묶지 않는다. 자동 OTA도 없다.

실물 단계의 완료 기준은 정상 부팅·USB 없이 Wi-Fi 재접속·위 호출어 실측·실제 한국어 STT/GPT/TTS·
중지/실패·전원 재시작 후 설정/예산 유지·노트북 없이 동작의 사용자 증거다.
실제24시간 운영, 카메라/센서 관찰, 모터 피드백/물리 중지와 자율 행동은 이후 별도 검증한다.

## 이후 순서

1. 위 독립 음성 펌웨어의 구현·빌드·검토.
