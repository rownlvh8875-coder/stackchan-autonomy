# StackChan Mock MVP Implementation Plan

> Execute inline using superpowers:executing-plans and test-driven-development.

**Goal:** Phase 0–3, an offline autonomous robot loop with fail-closed actions.
**Architecture:** Separate perception, decision, behavior/events, memory, action and
safety. Typed ports isolate FakeRobot and Responses API. One action consumer owns
commands; STOP latches synchronously and cancels the active cycle.
**Tech:** Python >=3.11, uv, asyncio, Pydantic, OpenAI Responses, MCP SDK, pytest, ruff.
**Spec:** ../../DEVELOPMENT_BRIEF.md (user supplied; execute without a planning stop).

## Global constraints
- No physical device commands, firmware modification, or remote publication.
- Default mock, dry run, cloud/image/audio transmission disabled.
- Existing isolated /workspace checkout; no additional worktree.
- Models configured by environment, secrets excluded from logs and Git.
- Pin dependencies and record upstream SHA; do not copy firmware.

## Review focus
Cancellation between validation and dispatch; stale absolute poses; ambiguous
network execution; malformed/refused cloud output; bounded queues and histories.

## Interface decisions
- RobotAdapter: status(), capture(), execute(RobotCommand); asynchronous.
- DecisionProvider: decide(Observation, DecisionContext) -> Decision.
- Engine: submit(Event), step(Event), run(), stop(); queue is bounded, STOP bypasses it.
- ActionExecutor: execute(Decision, now) -> ActionResult, stop(); one bounded worker.
- Memory: bounded summaries only, optional SQLite metadata; no media or raw dialogue.
- Physical MCP implementation remains a disabled Phase 4 seam until explicit approval.
