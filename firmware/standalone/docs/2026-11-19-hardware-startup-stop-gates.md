# K151 주변장치 기동·STOP 정책 (2026-11-19)

**컴파일 및 호스트 가짜 드라이버 검증 전용. 실물 구동·설치 금지.**

제조사 고정 소스
`m5stack/StackChan@28b9f0c8bd6acd81cb3c70f1a93c3e373b39d400`의
`firmware/main/hal/hal.cpp`는 `Hal::init()`에서 NVS 실패 시
`nvs_flash_erase()`를 호출하며, 터치·I/O 확장·서보·LVGL을 연이어
초기화한다. 단독 개발 펌웨어에는 이 함수를 가져오지 않는다.
`stackchan.cc`의 AXP2101·AW9523 설정 및 ILI9342C/E 경로는 전원과
LCD 리셋을 바꿀 수 있으므로 장비 검증 전에는 실행하지 않는다.

### 오프라인 중지 감시기

`core/hardware_hold.hpp`의 `PeripheralStopSupervisor`는 STOP이 오면
**모든 주변장치 콜백보다 먼저** 원자적 중지 래치를 설정하고
`Session::stop()`, `PersistentGuard::cancel_permit()`를 실행한다.
그다음 마이크 OFF → 앰프 OFF → HTTP 중단 → USB 종료 →
LVGL 해제 → 공유 I2C 해제를 한 번씩 시도한다. 한 콜백이
실패해도 남은 종료 콜백을 호출하되, 실패를 정상이라고 보고하거나
자동 재시작하지 않는다.

이 순서는 호스트의 가짜 콜백으로만 검증되었다. 실제 물리적
전원 차단, 하드 STOP 인터럽트, 오디오 출력 지연, USB 버퍼 잔량,
장치 종료 소요시간, 핀 전기 상태는 **미측정**이다.

### 기동 보류

`RecoveryReadiness`는 사용자 원본 백업 일치와 별도 사본, 복구 경로,
활성 OTA 슬롯, 실제 패널 종류, 공유 I2C 독점·전원·앰프 뮤트,
물리적 STOP 실측, 신규 설치 승인 등을 **독립된 증거로** 요구한다.
이 항목을 모두 만족한다고 주장해도 `kHardwareActivationInHoldImage`
값이 `false`여서 이번 바이너리에서는 하드웨어를 시작할 수 없다.
`app_main`은 컴파일 링크 문자열을 출력하는 것 외에 이 코어를
호출하지 않는다. 설치할 수 있는 새 펌웨어 이미지로 배포하지 않는다.

**다음 판단:** 원본 전체 16MB 백업 A/B를 제3의 오프라인 매체에도
보존했는지, 실제 복구 가능성을 보장할 절차가 무엇인지,
실물 화면·전원·앰프·STOP을 어떻게 계측할지 별도로 검증해야 한다.
공장 인증/공식 앱 호환은 현재 증명되지 않았다.
