# K151 independent Wi-Fi / clock / secret policy (2026-11-19)

**Development/CI only. Do not install or activate this code on the user's K151.**

- Portable `network_time_guard.hpp` has no ESP-IDF, network socket, flash or I/O calls.
- `RuntimeSecrets` stores credentials and API tokens in bounded in-process arrays only; explicit physical/local-owner input is required. It wipes its own buffers on clear/destruction; this does **not** assert that external caller buffers are erased or that secrets are immune to RAM inspection. Credential values are not written to source control, logs or NVS.
- The current backed-up board has flash encryption disabled. An unencrypted `sc_gpt` NVS namespace is **not** an encrypted secret store. Permanent Wi-Fi/API token provisioning remains blocked until separate authenticated/encrypted storage and physical-owner workflow are designed and verified. RAM-only credentials are lost on power cycle; the final unattended PC-free operation is **not** yet complete.
- Network state cannot become eligible for paid calls until a separately authorized Wi-Fi association, IP acquisition and fresh plausible SNTP sample. Disconnection invalidates readiness immediately; attempts use 1, 2, 4, 8, 16, 32, max 60 seconds of backoff. There is no automatic replay of a previous voice request.
- Clock-anchor plausibility rejects time rollback, >10-second system-clock drift, >15-minute stale synchronization, and >10-second jumps after reconnect. The `BudgetLedger` separately refuses timestamp rollback. **Ordinary SNTP is not cryptographically authenticated and does not prove UTC accuracy**, especially after reboot; a large unauthorized forward jump or off-device clock tampering can still corrupt rate-window accounting. Local paid consent, hard request budgets, and independent API billing controls remain required.
- The policy must be mutated only from one owning task. ESP event callbacks must queue bounded events and ignore stale attempts; no event handler may directly mutate this class on an arbitrary FreeRTOS task.
- STOP prevents reconnect, stops admission of requests and leaves network readiness false. Network pause/reconnect never retries API transactions already potentially billed.
- Tested locally with g++ 14 `-std=c++20 -Wall -Wextra -Werror -pedantic`, ASan/UBSan, and offline pytest. Tests cover secrets validation and wipe, denied first-time owner consent, event ordering, stale attempt identifiers, reconnect backoff, clock age, time jumps, bad wall time, STOP and monotonic rollback. This is NOT a chip-target build, real Wi-Fi association, secure key storage, or SNTP connectivity proof.

Official ESP-IDF fixed source: [esp_wifi.h](https://github.com/espressif/esp-idf/blob/fff9895c82d744c7237be8847347bdd1b07c6643/components/esp_wifi/include/esp_wifi.h) notes `esp_wifi_connect()` attempts once and `esp_wifi_set_config()` normally saves settings in NVS. A future device adapter MUST explicitly use RAM-only Wi-Fi storage (`WIFI_STORAGE_RAM`, and disable Wi-Fi NVS on initialization), never `esp_wifi_restore()` or NVS erasure. [esp_netif_sntp.h](https://github.com/espressif/esp-idf/blob/fff9895c82d744c7237be8847347bdd1b07c6643/components/esp_netif/include/esp_netif_sntp.h) defines SNTP event and sync APIs. These device APIs are **not invoked in this portable stage**.

## Dormant ESP-IDF adapter (next commit)

`esp_app/main/k151_wifi_time.{hpp,cpp}` implements a guarded, **not-started** ESP-IDF v6.1 Station+SNTP port. It is compiled into the independent HOLD image but only its `compiled_link_marker()` is called at boot. No `esp_wifi_init`, `esp_wifi_start`, `esp_wifi_set_config`, SNTP or event handlers execute at startup.

- Its `start()` is gated by a separately authenticated physical/local owner decision, unexpired RAM-only `RuntimeSecrets` inputs and an unlatched STOP. No USB opcode or remote API can provide those approvals in the current application.
- Before invoking `esp_wifi_set_config`, it sets `wifi_init_config_t::nvs_enable=0` and `WIFI_STORAGE_RAM`. Code does not invoke `esp_wifi_restore`, factory credential reads, NVS erasure or log credential values. Firmware `sdkconfig.defaults` also disables Wi-Fi NVS storage. This is a source-level safeguard, not a field-proven guarantee of flash immutability on the target.
- A bounded FreeRTOS queue carries Wi-Fi connection, disconnect, IP and SNTP events to a single owning task. The ESP event callback immediately raises an atomic `link_down` latch on disconnection, so paid-work eligibility is revoked even before the task drains its queue. Queue overflow is a permanent fault.
- The owning task uses the portable backoff/clock policy; SNTP starts only after IP acquisition, after which a plausible clock update can mark readiness. No pending paid request is retried on reconnect. `shutdown()` attempts resource cleanup, invalidates eligibility and wipes the local copy of credentials.
- This is **compile-only**. The adapter has not been exercised on any physical network, and event races, Wi-Fi memory, delayed callbacks, NVS semantics, request interruption time, packet loss, and recovery after a device reset remain unverified. A synchronous HTTPS client must separately check link/clock state between I/O calls, not only at the start of the transaction.
